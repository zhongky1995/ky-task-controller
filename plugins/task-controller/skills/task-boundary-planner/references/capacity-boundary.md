# Capacity and Support

Use when volume, dependencies or professional capability threaten the current commitment. Assess the concrete constraint; do not assign a high/low label and mechanically select a workflow.

A large routine transformation may need batching and progress markers. A small strategic, editorial or technical choice may need better evidence or expertise. These are different problems: more workers or more output cannot compensate for a missing judgment.

Consider the relevant drivers: material that must be understood together, dependent artifacts, available tools and expertise, verification consequences, and the user's time/cost constraints. State only the limitation that changes the next action. No universal one-pass envelope, capacity score or preliminary inventory is required.

Keep cohesive work with a continuing owner when it can be handled reliably. Batch independent material when that preserves meaning. Use a representative piece when it can resolve a consequential uncertainty before expanding, not as a mandatory sample gate. Maintain the overall purpose and how each part contributes; a successful fragment does not establish whole-artifact quality.

If the crucial part remains unreliable despite sufficient materials, seek better professional evidence or an appropriate capability, or propose a bounded change in commitment. Ask the user only for a reserved tradeoff or missing authority. Continue useful independent work; do not quietly lower the promised outcome.

For an already managed KY-TASK contract, respect its actual budgets, dependencies, sample gates and review requirements. A real scope or authority change follows the existing revision protocol. Adding workers, replacing context or renaming a batch does not reset prior failures or spending limits.
