# Execution Handoff

Use when meaningful work is actually changing hands. The planner supplies the current outcome, relevant boundaries and dependencies; the controller applies the runtime protocol. Do not turn a planning handoff into another approval phase or duplicate worker configuration templates here.

## Preserve the judgment

Link the current artifact and effective decisions, including the reasons that matter to the next choice. Explain what the contribution is for, which inputs are dependable, what remains uncertain, and how its result will be used. Reuse the project's current entrypoint; avoid making the recipient reconstruct intent from a long transcript or only the latest correction.

Keep closely coupled definition and production with one continuing owner where practical. A separate researcher, designer or reviewer does not replace that owner's responsibility to inspect and integrate the actual result. Hand off a responsibility only when the expected benefit outweighs lost context and setup. Do not create a lane per professional consideration, step or document.

## Choose and continue the actual execution mode

[Working agreement](../../task-controller/references/working-agreement.md) is the maintained source for direct, sequential or distributed execution, existing-role preservation and authority. A bounded execution request permits its work; planning-only remains planning-only. A generic execution request does not authorize visible conversations. Existing explicit task-scoped coordination authority need not be requested again.

For a KY-TASK multi-lane plan, use [work orchestration](../../task-controller/references/work-orchestration.md) to derive dependencies from actual input/output consumption and identify the semantic owner. Keep shared-target writes serialized and independent investigations eligible for parallel work. Verification consumes the artifact or decision it judges. These operational records serve the chosen workflow, not all ordinary tasks.

The controller owns runtime admission, project affinity, model settings, registration, callback and revision identity. Use [session orchestration](../../task-controller/references/session-orchestration.md) and [dispatch/recovery](../../task-controller/references/dispatch-and-recovery.md) for those exact mechanics. Under the installed Session-first policy, do not silently substitute managed workers or projectless Sessions. Reuse compatible idle Sessions when authorized; a new attempt does not itself require a new conversation.

## Integrate and continue

The recipient should inspect the relevant current work, implement its assigned contribution and report substantive decisions, actual changes, evidence and unresolved differences. Production can reveal a design mistake; raise it with concrete consequences and resolve within existing authority, rather than preserving a bad implementation for the sake of the handoff document.

The controller reads or uses the integrated artifact and judges it against the intended use. A passing callback establishes only its supported scope. Preserve useful results across corrections, update the effective decision where needed, and continue dependency-ready authorized work. Missing authority or a reserved choice pauses only dependent actions. Required independent review and machine gates remain binding.
